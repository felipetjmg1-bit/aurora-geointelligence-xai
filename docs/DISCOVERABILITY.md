# Discoverability and repository metadata

## Suggested repository description

> Experimental CPU-first geospatial image inspection MVP in Python: Rasterio metadata, reproducible visual clustering, optional NDVI/NDWI, and traceable JSON reports. No PyTorch model or production claims.

## Topics for the current repository state

The repository topics are intended to describe the code and research area without signaling an affiliation or capability that is not present. Suggested topics: `deep-tech`, `geospatial`, `geospatial-ai`, `remote-sensing`, `explainable-ai`, `auditability`, `sovereign-infrastructure`, `python`, `open-source`.

`explainable-ai` and `geospatial-ai` indicate the project's research direction and name; the README must continue to say that model-level XAI and deep-learning geospatial models are not implemented in the current MVP.

## Excluded until evidence changes

Do not add `pytorch` while it is absent from the dependencies and code. Do not add `neural-architecture` while the repository has no neural architecture. Do not use `mlcommons` or official-looking conformance/partnership badges unless an applicable benchmark, certification, membership or formal relationship is documented. Do not label the software production-ready, forensic-grade, court-validated or affiliated with Finep/CDTI without independent, verifiable evidence.

## Search-writing principles

Use natural technical terms where they accurately describe the implementation: geospatial image inspection, remote sensing, raster/GeoTIFF metadata, reproducible visual clustering, NumPy, Rasterio, MiniBatchKMeans, NDVI/NDWI, auditability and Python. Avoid keyword stuffing, benchmark claims without results, and phrases that equate a roadmap with an implemented feature.
